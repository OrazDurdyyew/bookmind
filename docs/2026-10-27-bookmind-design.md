# BookMind — описание первой версии

Дата: 2026-10-27
Статус: ждёт одобрения автора

Пометка **[моё решение]** значит, что пункт предложил я (Claude), а не автор идеи. Его можно оспорить.

---

## 1. Что это и зачем

BookMind — это приложение для Windows. Учитель загружает в него книгу, а **локальный ИИ, встроенный в приложение**, отвечает на вопросы по этой книге и составляет по ней тесты для печати.

Главная фишка: **всё работает на компьютере пользователя, без интернета и облака**. Программа ставится обычным установщиком на средний компьютер, без видеокарты и без технических знаний.

Книги могут быть на **туркменском, русском и английском**.

## 2. Для кого и как пользуются

Основной пользователь — **учитель**.

Типичный сценарий:
1. Учитель открывает BookMind. Раздел «Мои книги» пустой, на нём кнопка **«Загрузить книгу»**.
2. Учитель выбирает файл и нажимает **«Изучить эту книгу»**. Идёт процесс с прогрессом («62%, осталось ~3 мин»).
3. Книга появляется в списке **«Изученные книги»** с кнопками **«Задать вопрос»** и **«Создать тест»**.
4. «Задать вопрос» открывает чат по этой книге. Учитель пишет вопрос, ИИ отвечает.
5. «Создать тест» открывает настройку теста. Учитель получает готовый тест, правит его и печатает для учеников.

## 3. Цели, не‑цели, анти‑цели

**Цели первой версии**
- Чат по книге: ответы **только по тексту книги**, со ссылкой на главу или страницу.
- Создание тестов по одной главе, нескольким главам или всей книге, с печатью.
- Интерфейс на трёх языках: TM, RU, EN.
- Полностью офлайн после установки.
- Красивый, современный дизайн (стиль «светлый, свежий», см. раздел 8).

**Не входит в первую версию** (возможно, позже)
- Ответы с использованием общих знаний ИИ, не из книги.
- Прохождение тестов учениками внутри программы и автоматическая оценка.
- Сканированные PDF (картинки без текстового слоя), то есть OCR.
- macOS и Linux.
- Аккаунты, облако, синхронизация.

**Анти‑цели** (провал, даже если «технически работает»)
- **ИИ путает и выдаёт неправильные ответы.** Это главный риск: таким приложением никто не будет пользоваться. Лучше не поддерживать слабый компьютер, чем работать на нём плохо.
- Ответ выдуман, а не взят из книги, и учитель не может это проверить.
- Установка требует технических знаний: командной строки, ручного скачивания моделей и т. п.
- Приложение «висит» без объяснений во время долгих операций.

## 4. Функции первой версии

### 4.1. Библиотека «Мои книги»
- Загрузка через кнопку или перетаскиванием файла.
- Форматы: **PDF (с текстовым слоем), EPUB, DOCX, TXT** **[моё решение]**.
- Если в PDF нет текста (это скан), показываем понятное сообщение: «Эта книга — скан, такие пока не поддерживаются».
- Список книг: название, число страниц, язык книги, статус (изучается / изучена / ошибка).
- Книгу можно удалить.

### 4.2. «Изучение» книги (индексация)
- Программа извлекает текст, определяет **главы** и **номера страниц**, режет текст на фрагменты и строит поисковый индекс (векторный и текстовый).
- Главы определяются по оглавлению EPUB, закладкам PDF или заголовкам DOCX. Если глав найти не удалось, книга делится на части по страницам («стр. 1–30, 31–60…») **[моё решение]**.
- Язык книги определяется автоматически, учитель может его поправить.
- Видны прогресс и примерное оставшееся время. Изучение можно отменить. Если программу закрыли в процессе, при следующем запуске изучение продолжится или начнётся заново.
- Ориентир по размеру: книги до ~1000 страниц **[моё решение]**.

### 4.3. Чат по книге
- Каждый чат привязан к одной книге. Чаты сохраняются, их видно в разделе «Чаты».
- Ответ строится **только по найденным фрагментам книги**. Под ответом стоят ссылки «Глава 4, стр. 87». По клику показывается сам фрагмент текста.
- Что значит «страница» в ссылке **[моё решение]**: для PDF это **напечатанный номер страницы** (метки страниц PDF), если он есть, иначе порядковый номер страницы в файле. У EPUB, DOCX и TXT страниц нет, поэтому ссылка выглядит как «Глава 4, раздел „Фотосинтез“». Учитель должен легко найти это место в бумажной книге.
- Если ответа в книге нет, ИИ говорит: «В этой книге нет ответа на этот вопрос». Это обязательное поведение, мы его проверяем (раздел 5).
- Ответ появляется постепенно, по словам (стриминг). Генерацию можно остановить.
- Язык ответа совпадает с языком вопроса **[моё решение]**.

### 4.4. Тесты
**Настройка**
- Источник: одна глава, несколько глав (галочками) или «Вся книга».
- Тип вопросов: с вариантами ответа (4 варианта, один верный), открытые, да/нет. Типы можно смешивать.
- Количество: 5 / 10 / 20 или своё число.
- Сложность: лёгкий / средний / сложный.
- Язык теста по умолчанию совпадает с языком книги, его можно сменить **[моё решение]**.

**Создание**
- Если выбрано несколько глав, материал берётся **равномерно** из каждой, а не только из начала.
- Вопросы появляются по одному, виден прогресс («4 из 10»).
- Каждый вопрос опирается на текст книги. Учитель видит, с какой страницы взят правильный ответ.
- Модель выдаёт вопросы в строгом формате (JSON по схеме, через грамматику llama.cpp), чтобы тест не «ломался».

**Редактирование**
- Любой вопрос можно отредактировать вручную, удалить или нажать «Заменить другим».
- Тесты сохраняются в разделе «Тесты».

**Печать**
- Кнопки «Печать» и «Сохранить в PDF».
- **Лист для учеников**: без ответов, с полями «Имя», «Класс», «Дата».
- **Лист с ключом ответов** для учителя печатается отдельно.
- **Варианты А и Б** с перемешанными вопросами и вариантами ответов.
- Экспорт в Word не входит в первую версию **[моё решение]**.

### 4.5. Языки интерфейса
- TM / RU / EN, переключатель в верхней панели, выбор запоминается.
- Язык по умолчанию берётся из языка Windows, иначе RU **[моё решение]**.
- Все тексты интерфейса лежат в файлах переводов, ничего не «зашито» в код.

### 4.6. Настройки
- Текущая модель (Стандарт / Pro) и возможность её сменить.
- Язык интерфейса.
- Папка, где хранятся книги и данные.

## 5. Модели ИИ и проверка качества

### 5.1. Принцип
**Минимальные требования к компьютеру определяются самой маленькой моделью, которая проходит нашу проверку качества**, а не наоборот. Модели слабее порога не предлагаются вообще.

### 5.2. Проверка качества (делается первой, до основной разработки)
1. Набор проверочных материалов: главы из реальных книг на **tm, ru, en** (по 2–3 книги на язык). К ним 20–30 вопросов на язык с заранее известными правильными ответами, плюс вопросы, ответа на которые в книге **нет**.
   - **Туркменскую часть готовит автор идеи**: даёт книги и пишет или проверяет вопросы и ответы. Русскую и английскую готовит Claude.
   - Туркменский только на **латинице** (современная письменность). Кириллические туркменские книги не поддерживаются.
   - Оценка ответов **[моё решение]**: сначала автоматически (сравнение с эталоном, при необходимости большая модель в роли судьи), затем спорные ответы смотрит человек. Туркменские спорные ответы смотрит автор идеи.
2. Прогоняем 4–6 кандидатов. Ориентиры: Qwen3 1.7B / 4B / 8B, Gemma 3 4B / 12B, Phi‑4‑mini (квантизация Q4_K_M), плюс новые модели, вышедшие к моменту проверки.
3. Отдельно проверяем **модель для поиска** (embeddings), особенно на туркменском. Кандидаты: multilingual‑e5‑small/base, bge‑m3.
4. Метрики:
   - доля верных ответов в чате;
   - доля правильных отказов («нет в книге»);
   - доля корректных вопросов теста (верный ответ действительно верен, нет дублей, формат не сломан);
   - скорость (слов в секунду) на эталонном слабом ПК. Пока реального ПК нет, эталон **[моё решение]**: 4 ядра / 8 потоков уровня Intel Core i5‑6500, 8 ГБ ОЗУ, без видеокарты. Замеры делаются с ограничением llama.cpp до 4 потоков, а когда появится реальный школьный ПК, перепроверяются на нём.
5. Порог прохождения: **около 85% по каждому языку** (точное число уточним после первых прогонов) **[моё решение]**.
6. Набор проверок сохраняется и используется повторно при каждой смене модели.

### 5.3. Уровни моделей (прогноз, подтвердим проверкой)
| Уровень | Компьютер | Модель | Размер |
|---|---|---|---|
| **Стандарт** (минимум) | 8 ГБ ОЗУ, 4‑ядерный процессор с AVX2 (≈2016+) | ~4 млрд параметров | ~2.5–3 ГБ |
| **Pro** | 16+ ГБ ОЗУ и/или видеокарта | ~8 млрд параметров | ~5 ГБ |

**Результат первой проверки (2026-10-27, `eval/baseline-2026-10-27.md`), порог 85% по каждой метрике:**

| Язык | «Стандарт» (~4B) | Pro (~8–9B) | Лучший результат по ответам |
|---|---|---|---|
| en | ✅ проходит (gemma-3-4b, qwen3-4b, phi-4-mini, qwen3.5-4b) | ✅ (qwen3-8b, qwen3.5-9b) | 95–100% |
| ru | ❌ | ❌ | 75–85% (не хватает 1–2 ответов из 20) |
| tm | ❌ | ❌ | 56% (qwen3-4b); крупные модели не лучше |

- Эмбеддер для всех языков — multilingual-e5-base (~220 МБ).
- Скорость «Стандарт» на 4 потоках CPU: первый текст ответа 14–63 с (ru/en) и 52–124 с (tm) — цель раздела 9 (5–10 с) пока не достигнута.
- **Открыто (решение автора):** что делать с tm — ограничение «tm только Pro» из раздела 11 не помогает, Pro тоже не проходит.

- Видеокарта (NVIDIA, AMD, Intel) используется через Vulkan, если она есть.
- Лицензии моделей должны позволять бесплатное распространение. Предпочтение Apache 2.0 (Qwen); условия Gemma проверяем отдельно.

## 6. Установка и первый запуск

- Установщик для Windows 10/11 (64‑bit).
- **Главный способ — офлайн‑установка** (решение автора идеи). Установщик раздают на флешке или по локальной сети, интернет не нужен вообще.
  - `BookMind-Setup.exe` (~3–3.5 ГБ): приложение и модель «Стандарт» внутри.
  - `BookMind-Pro-*.bmpack`: отдельный пакет с моделью Pro (~5 ГБ). Если он лежит в той же папке, что и установщик, установщик сам предложит его поставить. Его можно добавить и позже через Настройки **[моё решение]**.
  - **Каждый файл меньше 4 ГБ**, потому что флешки с FAT32 не принимают файлы больше. Пакет Pro при необходимости делится на части **[моё решение]**.
  - Скачивание модели из интернета в первую версию не входит.
- **Первый запуск:**
  1. Проверка компьютера: ОЗУ, процессор (AVX2), видеокарта, свободное место.
  2. Рекомендованный уровень модели отмечен, пользователь может выбрать другой из подходящих.
  3. Если компьютер ниже минимума, показываем честное сообщение с требованиями и не ставим модель.
- Модели подготовлены, проверены и упакованы нами заранее. Пользователь ничего не знает о «моделях» кроме выбора «Стандарт / Pro».
- Подпись кода, чтобы не было предупреждения SmartScreen, желательна к публичному релизу. Для первой версии это не обязательно.

## 7. Технические решения

**Решено автором идеи**
- **Tauri**: интерфейс на HTML/CSS/TypeScript, «мотор» на Rust.
- **llama.cpp** как движок для локальной модели.
- **Код пишет Claude** и объясняет автору каждую часть. Автор учится по ходу, поэтому код должен быть понятным, с комментариями на ключевых местах, без «хитрой» магии.
- Жёсткого срока нет, но чем быстрее, тем лучше. Сначала делаем рабочее ядро (проверка моделей → изучение книги → чат → тесты и печать → установщик), а полировку потом.

**[моё решение]**
- llama.cpp запускается как отдельный процесс `llama-server.exe` (sidecar), Rust‑часть им управляет. Это проще и надёжнее, чем вшивать библиотеку напрямую.
- Интерфейс: React + TypeScript + Vite, иконки Lucide.
- Хранение: SQLite, один файл с книгами, фрагментами, индексом, чатами и тестами. Векторный поиск через sqlite‑vec или в памяти, текстовый через FTS5. Поиск гибридный (векторный + текстовый): это важно для туркменского, где векторная модель может быть слабее.
- Все данные лежат локально в папке пользователя (`%APPDATA%/BookMind`).

## 8. Дизайн

Выбран стиль **C, «Светлый, свежий»**. Макеты экранов «Мои книги», «Чат» и «Создание теста» лежат в `.superpowers/brainstorm/73706-1793044717/content/screens-c-v2.html`. Экраны, которых нет в макетах (редактор теста, лист для печати, первый запуск, настройки), разработчик делает в том же стиле.
- светлый фон `#f6f9fc`, белые карточки, тонкие рамки `#e4ebf2`;
- основной акцент бирюзовый `#14b8a6`, градиент логотипа `#0ea5e9 → #14b8a6`;
- шрифт Segoe UI (системный), скруглённые углы 8–12 px;
- **нормальные иконки Lucide**, без эмодзи;
- слева меню: Книги, Чаты, Тесты, внизу Настройки и текущая модель;
- сверху логотип BookMind и переключатель TM / RU / EN.

## 9. Ограничения
- Только Windows 10/11 x64.
- Полностью офлайн после установки (или после скачивания модели).
- Должно работать на «Стандарт»‑компьютере (раздел 5.3) с приемлемой скоростью: первый текст ответа в чате не позже ~5–10 секунд **[моё решение, уточним проверкой]**.

## 10. Оставлено на усмотрение разработчика
- Точный размер фрагментов, сколько фрагментов давать модели, формулировки системных промптов.
- Как именно перемешивать варианты А/Б и раскладывать страницы для печати.
- Внутренняя структура кода и базы данных.
- Порядок реализации внутри плана, но **проверка качества моделей (раздел 5.2) идёт первой**.

## 11. Риски
- **Туркменский язык**: маленькие модели работают с ним хуже. Если ни одна модель уровня «Стандарт» не пройдёт порог на tm, придётся поднимать минимум или ограничить tm уровнем Pro. Решение принимаем после проверки.
- **Сложная вёрстка PDF**: таблицы, колонки, сноски могут извлекаться с ошибками.
- **Размер установщика**: ~3.5 ГБ для «Стандарт», копировать по сети или на флешку долго.
- **Обновления**: без интернета новая версия тоже распространяется вручную (флешка/сеть).
- **Скорость на слабых ПК** при создании теста по всей книге: нужен понятный прогресс.
